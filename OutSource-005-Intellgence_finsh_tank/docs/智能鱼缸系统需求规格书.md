## 1. 项目概述

| 项目 | 内容 |
|------|------|
| **项目名称** | 基于 STM32 + RT-Thread 的智能鱼缸监控系统 |
| **目标描述** | 实现鱼缸水质环境的实时监测与自动控制，包括水温、水位、空气质量、PH值等参数的采集、OLED 显示、声光报警、WiFi 远程通信，以及排水/加水/增氧/加热等执行机构的自动/手动控制 |
| **主控平台** | STM32F103C8T6（ARM Cortex-M3, 72MHz, 64KB Flash, 20KB SRAM） |
| **操作系统** | RT-Thread v3.1.4（实时操作系统） |
| **开发环境** | RT-Thread Studio |
| **调试工具** | FinSH MSH 命令行终端 |

## 3. 按键功能定义

### 3.1 按键功能总览

> **按键隔离规则**：每个按键仅在其对应页面生效，其他页面按下无效（OLED 不刷新、数据不修改）。KEY1 是唯一在所有页面通用的按键。

| 按键 | 引脚 | 主页面 | 阈值设置页 | 手动控制页 |
|------|------|:------:|:---------:|:---------:|
| KEY1 | PA8 | ✅ 切换主页面 | ✅ 切换主页面 | ✅ 切换主页面 |
| KEY2 | PB3 | ✅ 子页翻页 | ✅ 子页翻页 | ❌ 无效 |
| KEY3 | PB4 | ❌ 无效 | ✅ 当前项 +1 | ✅ 开/关 切换 |
| KEY4 | PB8 | ❌ 无效 | ✅ 当前项 -1 | ❌ 无效 |
| KEY5 | PB1 | ❌ 无效 | ✅ 切换编辑项 | ✅ 切换控制项 |

- ❌ 无效：按下后 OLED 无任何反应（不清屏、不闪烁、不修改数据）

### 3.2 页面导航逻辑

```
主页面(P1/P2) ──KEY1──→ 阈值设置(P1/P2) ──KEY1──→ 手动控制
      ↑                                              │
      └────────────────── KEY1 ──────────────────────┘

子页切换: KEY2 在 P1 ↔ P2 间切换 (仅主页面和阈值设置页)
```

## 4. OLED 显示页面

> **字体说明**：使用 16×16 点阵汉字 + 6×12 ASCII 混合显示。OLED 为 128×64 像素，共 8 页（每 page = 8px 高）。
>
> **混合行布局**：每行 2 个 page（16px）。左侧汉字标签（16×16），右侧 ASCII 数值（6×12 下移 2px 对齐汉字基线）。汉字与 ASCII 间距 2px。
>
> **翻页机制**：每屏最多 4 行汉字。内容超出时放入子页，底部显示页码指示 `P1/2` 或 `P2/2`。
>
> **按键隔离**：仅对应页面的按键生效，详见 §3.1。
>
> **显示线程栈**：1024 字节（字体数据 1088 字节通过 `__attribute__((section(".rodata")))` 放入 Flash，不占 RAM）。



### 4.1 主页面（上电默认）

**子页 1/2 — 实时数据**
```
┌────────────────────┐
│ 温度    24.0C      │
│ 空气    320        │

```

**子页 2/2 — 模式与状态**

```
│ 模式    自动       │

```

### 4.2 自动阈值设置页

**子页 1/2 — 温度/空气**
```
┌────────────────────┐
│ 阈值    Set        │
│ 温下限  20.0C      │
│ 温上限  30.0C      │
│ 空气值  500        │
│         P1/2       │
└────────────────────┘
```

**子页 2/2 — PH/水位**
```
┌────────────────────┐
│ PH下限  6.5        │
│ PH上限  8.5        │
│ 水位低  %40        │
│ 水位高  %80        │
│         P2/2       │
└────────────────────┘
```

- 当前编辑项右侧显示 `<<` 标识
- KEY5 循环选择编辑项（共 7 项跨两子页）
- KEY3 加 1，KEY4 减 1（温度步进 1.0°C，PH 步进 0.1，水位步进 5%，空气步进 10）

### 4.3 手动控制页

```
┌────────────────────┐
│ 加热    OFF        │
│ 加水    OFF        │
│ 排水    OFF        │
│ 增氧    ON>K3      │
│         P1/1       │
└────────────────────┘
```

- KEY5 循环选择控制项（加热/加水/排水/增氧/报警/喂食）
- 当前选中项显示 `>K3` 提示
- KEY3 切换选中设备的开/关状态
- 仅 4 行显示，超出项通过 KEY5 循环滚出当前屏（选中项始终置顶显示）

### 5.1 系统配置

| 配置项 | 值 |
|--------|-----|
| RT-Thread 版本 | v3.1.4 |
| Tick 频率 | 1000 Hz（1ms） |
| 最大优先级数 | 32 |
| 主线程栈大小 | 2048 字节 |
| 主线程优先级 | 10 |
| FinSH 栈大小 | 4096 字节 |
| FinSH 优先级 | 20 |
| 启用组件 | Semaphore, Mutex, Mailbox, FinSH |

### 5.2 线程架构

| 线程名 | 优先级 | 栈大小 | 周期 | 职责 |
|--------|--------|--------|------|------|
| main | 10 | 2048 | - | 系统初始化、创建其他线程 |
| t_sensor | 15 | 1024 | 500ms | 传感器数据采集（温度/水位/PH/空气） |
| t_control | 12 | 1024 | 500ms | 自动控制逻辑判断 + 继电器操作 |
| t_display | 18 | 1024 | 1s | OLED 刷新显示 |
| t_key | 14 | 512 | 50ms | 按键扫描与事件处理 |
| t_alarm | 13 | 512 | 500ms | 报警逻辑判断 + 声光控制 |
| t_feed | 16 | 512 | 1s | 喂食倒计时 + 舵机控制 |
| t_wifi | 17 | 2048 | 事件驱动 | WiFi 通信（数据收发） |
| tshell | 20 | 4096 | - | FinSH 调试终端 |

### 5.3 线程优先级说明

- 优先级数字越小，优先级越高
- 控制线程（t_control）优先级高于显示线程（t_display），确保控制实时性
- WiFi 线程（t_wifi）使用信号量事件驱动，非忙等

### 5.4 IPC（进程间通信）机制

| IPC 对象 | 类型 | 用途 |
|----------|------|------|
| sem_sensor | 信号量 | 传感器数据采集完成通知 |
| sem_key | 信号量 | 按键事件通知 |
| sem_wifi_rx | 信号量 | WiFi 数据接收通知 |
| mutex_oled | 互斥量 | OLED 显示资源保护（防止多线程同时写屏） |
| mutex_data | 互斥量 | 传感器数据结构体保护 |
| mb_alarm | 邮箱 | 报警事件传递（报警类型 → 报警线程） |

### 5.5 设备驱动框架

RT-Thread 使用设备驱动框架（`rt_device`）管理硬件外设：

| 设备名 | 类型 | 说明 |
|--------|------|------|
| uart2 | UART | ESP-01S 通信串口 |
| adc1 | ADC | 三通道 ADC（PH/水位/空气质量） |
| pin | PIN | GPIO（继电器/LED/蜂鸣器/按键） |
| tim3_pwm | PWM | 舵机控制 |

> 部分外设（DS18B20/OLED）使用软件模拟时序，不走 `rt_device` 框架，直接 GPIO 操作。

## 6. 功能需求

### 6.1 环境监测模块

| 功能 ID | 功能名称 | 功能描述 | 线程 | 优先级 |

|---------|---------|---------|------|--------|

| F-DIS-002 | 阈值设置页 | 显示并可编辑各参数阈值 | t_display | P1 |
| F-DIS-003 | 手动控制页 | 显示并可手动切换各设备 | t_display | P0 |

### 6.3 控制模块

| 功能 ID | 功能名称 | 功能描述 | 条件 | 线程 |
|---------|---------|---------|------|------|
| F-CTL-001 | 温度控制 | 低于下限开加热，高于上限关加热 | 自动模式 | t_control |
| F-CTL-002 | 水位控制 | 高于上限开排水，低于下限开加水 | 自动模式 | t_control |
| F-CTL-003 | 增氧控制 | 空气质量 > 阈值时开增氧 | 自动模式 | t_control |
| F-CTL-004 | 喂食控制 | 倒计时归零触发舵机 3 秒 | 全模式 | t_feed |
| F-CTL-005 | 手动控制 | 用户按键强制开关各继电器 | 手动模式 | t_key |

### 6.4 报警模块

| 功能 ID | 报警源 | 触发条件 | 解除条件 | 线程 |
|---------|--------|---------|---------|------|
| F-ALR-001 | 温度越限 | 水温 < 下限 或 > 上限 | 回到正常范围 | t_alarm |
| F-ALR-002 | 水位异常 | 水位 < 下限 或 > 上限 | 回到正常范围 | t_alarm |
| F-ALR-003 | 空气超标 | 空气质量 > 阈值 | ≤ 阈值 | t_alarm |
| F-ALR-004 | PH越限 | PH < 下限 或 > 上限 | 回到正常范围 | t_alarm |

> 报警方式：响 0.5 秒 / 停 2 秒循环，报警事件通过邮箱（mb_alarm）传递给 t_alarm 线程处理。

### 6.5 模式切换规则

| 切换 | 动作 |
|------|------|
| 自动 → 手动 | 关闭所有继电器，用户按需手动开启 |
| 手动 → 自动 | 关闭所有设备 → 根据阈值重新判断各设备状态 |

> 模式切换时使用 `mutex_data` 保护共享数据。

### 6.6 通信模块（手机APP）

| 功能 ID | 功能 | 方向 | 说明 |
|---------|------|------|------|
| F-COM-001 | 实时数据上报 | MCU → APP | 温度、空气质量、水位、PH值、模式、喂食倒计时 |
| F-COM-002 | 模式切换 | APP → MCU | 远程切换手动/自动模式 |
| F-COM-003 | 阈值设置 | APP → MCU | 远程设置各参数阈值 |
| F-COM-004 | 设备控制 | APP → MCU | 仅手动模式下可开关各设备 |
| F-COM-005 | 喂食触发 | APP → MCU | 远程触发一次喂食 |
| F-COM-006 | 离线重连 | 自动 | WiFi 断开后后台每秒重试连接 |

> ESP-01S 通过 USART2（PA2=RX, PA3=TX），波特率 115200。使用 `rt_device` 框架管理串口，接收中断触发 `sem_wifi_rx` 信号量。

## 11. 系统启动流程

```
1. 上电 / 复位
2. RT-Thread 内核初始化
   ├── 系统时钟配置（72MHz）
   ├── 中断向量表
   ├── 内存堆初始化
   └── 调度器启动
3. 组件初始化
   ├── FinSH 终端初始化
   └── 设备驱动框架初始化
4. main() 线程启动
   ├── 外设初始化：GPIO → ADC → UART → OLED → DS18B20
   ├── 加载默认阈值参数
   ├── WiFi 连接（失败进入离线模式）
   ├── 创建 IPC 对象（信号量/互斥量/邮箱）
   ├── 创建业务线程（t_sensor/t_control/t_display/t_key/t_alarm/t_feed/t_wifi）
   └── OLED 显示主页面
5. 各业务线程开始运行
```

## 12. 与裸机版本的差异

| 对比项 | 裸机版本（Keil） | RT-Thread 版本 |
|--------|-----------------|----------------|
| 任务调度 | 定时器中断回调 | RT-Thread 线程调度 |
| 并发保护 | 无（关中断） | 信号量/互斥量 |
| 外设访问 | 直接寄存器/HAL | `rt_device` 设备框架 |
| 数据传递 | 全局变量 | 邮箱/信号量 |
