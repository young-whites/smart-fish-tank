## 1. 嵌入式开发坑点

### 1.1 DS18B20 1-Wire 时序问题

**问题描述**：DS18B20 温度读取偶尔返回 85.0°C 或 -127°C 异常值。

**原因分析**：
- 85.0°C 是 DS18B20 上电默认值，表示转换未完成就被读取
- -127°C（0xFF）表示总线通信失败，传感器未响应
- 1-Wire 协议对时序要求极为严格，中断嵌套会破坏微秒级延时

**解决方案**：
- 将 DS18B20 读取从 TIM2 中断移到主循环，避免中断嵌套干扰时序
- 增加有效值范围判断：`t > -50.0f && t < 125.0f`
- 异常时保留上次有效值，设置 `sensorError` 标志位

### 1.2 ADC 多通道轮询精度问题

**问题描述**：ADC 三通道（PA0/PA1/PA4）采集时，第二、三通道数据偏移或不稳定。

**原因分析**：
- STM32 ADC 单模块多通道切换后，采样电容需要充电时间
- `ADC_SampleTime` 设置过短导致采样不充分
- 通道间串扰：上一通道的残留电荷影响当前通道

**解决方案**：
- 采样时间设为 `ADC_SampleTime_55Cycles5`，给足充电时间
- 每次采集前重新配置通道 `ADC_RegularChannelConfig()`
- 采用顺序轮询而非 DMA，控制采集节奏（每 5ms 一个通道，15ms 完成一轮）

### 1.3 OLED I2C 软件模拟刷新闪烁

**问题描述**：OLED 全屏刷新时出现短暂闪烁或花屏。

**原因分析**：
- 软件模拟 I2C 速度不够快，全屏 1024 字节写入耗时较长
- 刷新过程中中断打断导致 I2C 时序异常

**解决方案**：
- 采用局部刷新策略：仅更新变化的页面区域
- 页面切换时先 `OLED_Clr_Screen()` 再渲染新内容
- I2C 写入时临时关闭中断（临界区保护）

### 1.4 ESP-01S AT 指令通信不稳定

**问题描述**：ESP-01S 偶尔不响应 AT 指令，或返回乱码，TCP 连接断开后无法自动恢复。

**原因分析**：
- ESP-01S 上电后需要足够的启动时间（建议 > 1s）
- AT 指令之间需要间隔（建议 > 500ms）
- 串口波特率 115200 在某些 ESP-01S 模块上不稳定
- TCP Server 模式下客户端断开后需要重新配置

**解决方案**：
- `ESP01S_Init()` 中每个 AT 指令后加适当延时
- 增加 `ESP01S_EnsureServer()` 函数，定期检查 TCP Server 状态
- 环形缓冲区接收 + 主循环解析，避免中断中做复杂处理
- 连接状态检测：解析 `+CONNECT` / `+DISCONNECT` 通知

### 1.5 TIM2 中断中不宜做耗时操作

**问题描述**：在 TIM2 1ms 中断中调用 DS18B20 读取函数，导致其他周期任务严重延迟。

**原因分析**：
- DS18B20 单次转换需要 ~750ms（12位精度），即使不等待转换，复位+读取也需要数百微秒
- 1ms 中断中执行数百微秒的操作会阻塞后续中断，导致整个调度系统紊乱

**解决方案**：
- DS18B20 放在主循环中处理，非中断上下文
- TIM2 中断只做轻量级操作：GPIO 读取（按键）、ADC 启动转换、标志位设置
- 500ms 和 1s 任务只做逻辑判断和标志位操作，不做 I/O 阻塞

### 1.6 舵机 PWM 抖动问题

**问题描述**：SG90 舵机在某些角度出现抖动或嗡嗡声。

**原因分析**：
- PWM 周期或占空比计算精度不够
- TIM3 时钟配置或预分频器设置不正确
- 舵机供电不足（STM32 3.3V 无法驱动，需独立 5V 供电）

**解决方案**：
- 精确计算脉宽：`pulse = 500 + angle * 2000 / 180`（500~2500μs 对应 0~180°）
- TIM3 预分频设为 72-1，周期设为 20000-1，得到精确的 50Hz / 20ms
- 舵机使用独立 5V 电源，与 STM32 共地

### 1.7 按键消抖策略选择

**问题描述**：按键响应不灵敏或一次按下触发多次事件。

**原因分析**：
- 机械按键抖动时间约 5~20ms
- 消抖间隔太短（< 10ms）无法有效消抖
- 消抖间隔太长（> 100ms）导致按键响应迟钝

**解决方案**：
- 采用两层扫描策略：
  - `KEY_DrvScan()`（1ms）：读取 GPIO 电平写入缓冲区
  - `KEY_Scan()`（50ms）：连续 3 次确认消抖，生成按键事件
- 50ms 间隔 × 3 次 = 150ms 消抖窗口，既可靠又不迟钝

### 1.8 继电器互斥逻辑遗漏

**问题描述**：加水和排水继电器偶尔同时开启，导致水泵空转损坏。

**原因分析**：
- 自动控制逻辑和手动控制逻辑可能同时修改继电器状态
- 模式切换瞬间（自动→手动）未清零继电器

**解决方案**：
- 主循环中增加互斥检查：Fill + Drain 同时 ON 时，Drain 优先
- 模式切换时清零所有继电器
- 手动模式增加安全超时：60 秒无操作自动关闭所有继电器

## 2. Android APP 开发坑点

### 2.1 TCP 连接生命周期管理

**问题描述**：APP 切换到后台再回来时，TCP 连接已断开但 UI 仍显示已连接。

**原因分析**：
- Android 系统可能回收后台应用的网络资源
- Socket 超时或 Keep-Alive 机制未正确工作

**解决方案**：
- 启用 TCP Keep-Alive：`sock.keepAlive = true`
- 实现自动重连机制（最多 5 次，递增间隔）
- 通过 `SharedFlow` 监听连接状态变化，UI 实时响应
- 用户手动断开标记 `manualDisconnect`，避免自动重连

### 2.2 二进制帧协议解析边界问题

**问题描述**：偶尔收到不完整帧或帧粘包，导致数据解析错误。

**原因分析**：
- TCP 是流式协议，不保证消息边界
- 一帧数据可能被拆分到多个 TCP 包，或多帧粘连在一个包中

**解决方案**：
- 实现 `extractFrame()` 方法：从缓冲区中查找帧头 0xAA，根据 LEN 字段计算帧长
- 不完整帧保留在缓冲区，等后续数据到达后继续解析
- 校验和验证：`SUM = CMD + LEN + payload bytes`，末字节必须匹配
- 帧尾验证：最后一字节必须为 0x55

### 2.3 Compose 状态管理与协程

**问题描述**：UI 状态更新不及时或出现 `ConcurrentModificationException`。

**原因分析**：
- `MutableStateFlow` 在多个协程中同时写入
- `collect` 在错误的 Dispatcher 上执行

**解决方案**：
- ViewModel 中使用 `viewModelScope` 管理协程生命周期
- `TcpClient` 在 `Dispatchers.IO` 上执行网络操作
- 使用 `collectAsStateWithLifecycle()` 替代 `collectAsState()`，感知生命周期
- `SharedFlow` 设置合理的 `extraBufferCapacity`

### 2.4 WiFi 扫描权限问题

**问题描述**：Android 13+ 设备上 WiFi 扫描失败。

**原因分析**：
- Android 13 (API 33+) 对 WiFi 扫描权限有新要求
- 需要 `NEARBY_WIFI_DEVICES` 权限而非旧的 `ACCESS_FINE_LOCATION`

**解决方案**：
- `minSdk` 设为 34，只支持 Android 14+
- 使用 `WifiManager.getScanResults()` 获取扫描结果
- 权限申请时使用 `NEARBY_WIFI_DEVICES`

## 3. 系统集成经验

### 3.1 WiFi 通信协议设计

**经验总结**：
- 采用二进制帧协议（0xAA...0x55）而非文本协议，减少数据量和解析复杂度
- 命令字分区设计：MCU→APP 用 0x01~0x0F，APP→MCU 用 0x10~0x2F，便于扩展
- 校验和机制必须有，ESP-01S 透传可能丢数据
- 传感器数据上报周期 3s 较为合理，过快会阻塞 ESP-01S

### 3.2 数据同步策略

**经验总结**：
- APP 首次连接时发送 `CMD_QUERY_STATUS` (0x10)，MCU 主动上报一次全量数据
- 阈值参数由 APP 端主动同步到 MCU，MCU 不持久化存储（掉电丢失）
- 继电器状态变更后，MCU 在下次上报时同步给 APP

### 3.3 异常处理和容错

**经验总结**：
- DS18B20 断线检测：异常时保留上次有效值，设置 error 标志
- ESP-01S 断线恢复：`ESP01S_EnsureServer()` 定期检查，自动重建 TCP Server
- 手动模式安全超时：60 秒自动关闭继电器，防止 APP 意外断开后继电器一直开启
- 继电器互斥：加水/排水不能同时开启，硬件层面也应加互锁

## 4. 最佳实践建议

### 4.1 嵌入式开发

1. **中断中只做轻量操作**：读 GPIO、启动 ADC、设置标志位，绝不做阻塞 I/O
2. **传感器读取放主循环**：DS18B20 等时序敏感器件远离中断
3. **ADC 多通道切换要留裕量**：采样时间宁长勿短
4. **继电器必须有互斥逻辑**：加水/排水同时开启是灾难性的
5. **手动控制必须有超时保护**：APP 断开后继电器不能一直开着

### 4.2 Android 开发

1. **TCP 粘包/拆包必须处理**：实现帧提取器，不要假设每次 recv 就是一帧
2. **自动重连要有上限**：避免无限重连消耗电量
3. **ViewModel 管理协程生命周期**：使用 `viewModelScope`，避免内存泄漏
4. **UI 状态与连接状态解耦**：连接断开时 UI 应显示"断开"而非旧数据

### 4.3 系统集成

1. **协议版本号**：帧格式预留版本字段，方便后续升级
2. **心跳机制**：APP 定期发送查询命令，MCU 超时未收到则认为客户端断开
3. **OTA 考虑**：ESP-01S 支持 OTA，但本项目未实现，建议后续加入
4. **日志与调试**：保留 USART1 调试串口输出，生产环境可关闭
